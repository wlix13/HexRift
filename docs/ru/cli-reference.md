# Справочник CLI

Все команды требуют переданную топологию в YAML. По умолчанию путь — `conglomerate.yaml`.
Можно переопределить это значение с помощью опции `--yaml`:

```bash
hexrift --yaml conglomerate.yaml <команда> [опции]
```

## Глобальные опции

| Опция | По умолчанию | Описание |
|-------|-------------|----------|
| `--yaml PATH` | `conglomerate.yaml` | Путь к YAML-файлу топологии |
| `-V, --version` | — | Показать версию и выйти |

---

## validate

```bash
hexrift validate
```

Проверить YAML-топологию по Pydantic-схеме и вывести все ошибки.

**Вывод при успехе:**

```bash
Valid — conglomerate.yaml
  2 groups, 5 users, 2 exit regions, 1 hub regions, 6 nodes
```

**Вывод при ошибке:** выводит описание ошибки валидации и прерывает выполнение.

## show

```bash
hexrift show
```

Визуализировать полную топологию сети в виде дерева Rich: глобальные настройки, регионы, узлы, пользователи (сгруппированные по группам), порталы и гости.

## derive

```bash
hexrift derive <entity>
```

Отобразить деривированные идентификаторы в виде таблицы.

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `users` | UUID, email, server UUID и guest shortId для каждого пользователя |
| `groups` | ShortId для каждой группы |
| `nodes` | ShortId / hub-exit UUID для каждого узла |
| `all` | Всё вышеперечисленное |

**Примеры:**

```bash
hexrift derive users
hexrift derive all
```

## nodes

```bash
hexrift nodes [--names | --domains] [--type exit|hub]
```

Вывести список узлов с их именами хостов. Предназначена для использования в shell-скриптах.

**Опции:**

| Опция | Описание |
|-------|----------|
| `--names` | Выводить только идентификаторы узлов (по одному на строку) |
| `--domains` | Выводить только имена хостов (по одному на строку) |
| `--type exit\|hub` | Фильтр по типу региона |

**Примеры:**

```bash
# ID + hostname через табуляцию (по умолчанию)
hexrift nodes

# Все идентификаторы exit-узлов — удобно для циклов
hexrift nodes --names --type exit

# Все имена хостов hub-узлов
hexrift nodes --domains --type hub
```

## share

```bash
hexrift share <username> [опции]
```

Сгенерировать VLESS-ссылки для пользователя.

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `USERNAME` | Имя пользователя из `users[].username` |

**Опции:**

| Опция | По умолчанию | Описание |
|-------|-------------|----------|
| `--hub HUB_ID` | все hub-узлы | Сгенерировать ссылку для конкретного hub-узла |
| `--fp FINGERPRINT` | `edge` | TLS-отпечаток клиента |
| `--cdn` | выкл. | Сгенерировать CDN-ссылку вместо прямой Reality-ссылки |
| `--guest LABEL` | — | Сгенерировать ссылку для конкретного гостевого идентификатора |
| `--all-guests` | выкл. | Сгенерировать ссылки для всех гостей пользователя |
| `--bare` | выкл. | Выводить только чистые URL без форматирования — удобно для передачи |
| `--keys-dir PATH` | `keys` | Директория с файлами ключей |

!!! note
    `--guest` и `--all-guests` взаимно исключают друг друга.

**Примеры:**

```bash
# Прямая Reality-ссылка для alice на всех hub-узлах
hexrift share alice

# CDN-ссылка на конкретный hub
hexrift share alice --cdn --hub euH00

# Все гостевые ссылки, переданные в буфер обмена
hexrift share alice --all-guests --bare | clip
```

## gen-keys

```bash
hexrift gen-keys [NODE_ID | --all] [опции]
```

Сгенерировать пары ключей x25519 Reality и ключи шифрования ML-KEM 768. Для каждого узла записывается файл `<keys-dir>/<nodeId>.yaml`.

!!! info
    Hub-узлы в одном регионе автоматически используют общую пару ключей.

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `NODE_ID` | Сгенерировать ключи для одного узла |

**Опции:**

| Опция | По умолчанию | Описание |
|-------|-------------|----------|
| `--all` | выкл. | Сгенерировать ключи для всех узлов топологии |
| `--force` | выкл. | Перезаписать существующие файлы ключей |
| `--keys-dir PATH` | `keys` | Директория для хранения файлов ключей |

**Примеры:**

```bash
# Один узел
hexrift gen-keys nlA00

# Все узлы с перезаписью существующих
hexrift gen-keys --all --force

# Нестандартная директория
hexrift gen-keys --all --keys-dir /etc/hexrift/keys
```

## build

```bash
hexrift build [NODE_ID | --all] --xray|--haproxy [опции]
```

Сгенерировать `config.json` Xray и/или `haproxy.cfg` для узла(ов). Результат записывается в `<out-dir>/<nodeId>/`.

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `NODE_ID` | Собрать конфиг для одного узла |

**Опции:**

| Опция | По умолчанию | Описание |
|-------|-------------|----------|
| `--xray` | выкл. | Собрать `config.json` для Xray |
| `--haproxy` | выкл. | Собрать `haproxy.cfg` для HAProxy |
| `--all` | выкл. | Собрать конфиги для всех узлов |
| `--out-dir PATH` | `configs` | Выходная директория |
| `--keys-dir PATH` | `keys` | Директория с файлами ключей |

!!! warning
    Необходимо указать хотя бы один из флагов: `--xray` или `--haproxy`.

**Примеры:**

```bash
# Xray-конфиг для одного узла
hexrift build nlA00 --xray

# Все узлы, Xray и HAProxy
hexrift build --all --xray --haproxy --out-dir ./out

# Нестандартные директории
hexrift build euH00 --xray --keys-dir /etc/hexrift/keys --out-dir /etc/xray
```

## diff

```bash
hexrift diff <NODE_ID> [опции]
```

Показать unified diff между свежесгенерированным `config.json` и текущим задеплоенным.

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `NODE_ID` | Узел для сравнения |

**Опции:**

| Опция | По умолчанию | Описание |
|-------|-------------|----------|
| `--current-dir PATH` | `configs` | Директория с задеплоенными конфигами |
| `--keys-dir PATH` | `keys` | Директория с файлами ключей |

**Примеры:**

```bash
# Сравнение с локальной директорией configs/
hexrift diff nlA00

# Сравнение с задеплоенным конфигом
hexrift diff nlA00 --current-dir /etc/xray
```

Вывод подсвечивается с темой Monokai. При отсутствии различий выводит `No differences.`
